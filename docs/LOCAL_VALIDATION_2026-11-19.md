# Local Candidate Validation — 2026-11-19

The E89 app and widget package is prepared for a bounded hardware trial.
Its package, source reconstruction and simulated controller session passed
separate local checks. This is not a released or qualified daily monitor.
No real UPS session was performed with E89 during these checks.

## Native reader and source reconstruction

The optional [HIDAPI 0.16 profile](../backend/nut/native-build/hidapi-0.16/README.md)
uses upstream commit `750c87abb03282a237297052b84522e6bb3c0616` after the
[write-cancellation boundary correction](../backend/nut/native-build/WRITE_CANCEL_BOUNDARY.md).
Cancellation before a native write is distinguished from actual negative or
short writes; actual write errors remain failures. HIDAPI's macOS writes
remain synchronous, so these changes do not guarantee cancellation of a
blocked operating-system call.

The upstream pure-memory queue tests passed 22 cases. A separate fake-HID
full-driver replay retained six cancellation/error outcomes. Neither test
opened an actual or virtual HID device.

The native reader compiled locally with Xcode 27.2 build 27B52, SDK 27.2,
ARM64 and minimum macOS 27.0. A reconstruction from the private effective-source
kit verified three successive 190-file source stages, eight upstream vendor
files and seven reused generated inputs. These inputs include five static
archives and two headers; they were verified, not regenerated by this check.

With absolute normalized compile paths, all nine on-disk sections matched
the original unsigned reader. The complete binaries differed in the 16-byte
Mach-O `LC_UUID`. A relative-path build also succeeded but embedded a different
source-name string; it is not the equivalent reconstruction. Both products
remained unexecuted. This is not an independent-host or fresh-bootstrap result.

## Local package

The E89 archive contains 83 entries. The app, widget, helper and native-reader
signatures were verified before and after restoration and in the stable
local copy. The helper and nine effective runtime modules are unchanged from
the preceding E87 package; the capture still requests cancellation at 90 s.
The runtime manifest and inventory bind the newly signed reader. A static
consumer accepted the E89 manifest and rejected the prior E87 manifest.

The private package SHA-256 is

frozen frontend snapshot and overlays with native source, generated inputs,
runtime modules and notices. It does not silently update historical build
recipes or the legacy developer-kit exporter.

## H14 controller simulation

A separate fake producer exercised the controller without starting the real
E89 app or reader. One nominal session produced eight samples. The host
observed seven while active and retained two progressive copies. Stop was
requested 35.034 s after the first fresh sample and 35.488 s after Start;
the host completed at 35.531 s. The final state was `stopped/cancelled`, the
90 s protection did not fire, and owned processes and channels were released.
The session marker was absent after closure.

Missing authorization and ticket, a wrong manifest, a wrong producer and a reused ticket
were rejected. Offline counterchecks also rejected a missing terminal feed
and a byte-discordant terminal copy. No second capture session was started.
An independent reviewer checked source bindings, receipts and cleanup.

Two earlier admissions had stopped before any host, ticket or Start because
Finder metadata invalidated the synthetic bundle signature. The same archive
passed signature verification in isolated temporary storage. Only the fake
fixture and its location bindings were moved; the real candidate was unchanged.
The temporary fixture was removed after review.
