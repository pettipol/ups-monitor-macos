# Compatibility and Qualification

This table separates observations, source settings and synthetic checks. It does
not promise support beyond the evidence recorded here.

| Area | Evidence | Status / limit |
|---|---|---|
| H13 bounded terminal trial, SMC1500I (2026-11-06) | The E66 reader produced eight fresh samples, including charge, estimated runtime, load, input/output voltage and frequency, output current, battery voltage and temperature. The driver derived W and VA from load and nominal ratings. The captured fields had no energy counter. | Stop was requested while active about 35 seconds after the first fresh sample. The reader ended with `guard_error`. Its process and channels closed, ownership was released, the time fuse stayed idle, and macOS still detected the UPS. Normal Stop, sustained monitoring and desktop widget updates remain open. |
| Apple service, E84 source kit (2026-11-06) | The project's `ups-probe --session` reported one online UPS with battery charge and battery voltage. Runtime was unavailable. This uses the Apple reader and snapshot adapter that also supply the app's default mode. | One observation of the macOS power-source service. The probe does not publish to the widget. The E84 window was tested separately with simulated data. |
| E84 local app and widget package (2026-11-06) | A second export reproduced the 525-file source tar and its offline kit byte for byte. The signed app and widget were built from that snapshot. After extraction, four signatures and the contents, modes and link targets of the five components retained from E80 were verified. The extracted app finished launching in synthetic preview mode, displayed a main-sized window and quit normally. | This run observed window presence and the app lifecycle. Widget rendering, advanced hardware acquisition, installation from a download and operation on a second Mac remain separate checks. |
| E81 component mapping for E80 | The exact archived helper was inspected with authenticated PyInstaller readers. The inventory covers 157 PYZ names, 152 ZIP entries, nine project Python modules and their notice associations. The packaged libpython code/data matches the pinned PBS library. Sixteen declared extension initializers are defined in instruction-bearing sections, with their referenced notice texts present. | Static component and notice mapping. Compiled Python source-path associations are nominal. Applicable distribution terms and corresponding-source delivery remain a maintainer review. See [component inventory](FROZEN_PAYLOAD_COMPONENTS.md). |
| E66 bounded SMC1500I package | The helper completed a requested Stop after two samples with a synthetic producer. On 2026-11-06, H12 opened the signed E66 app and observed idle mode. The first UI lookup took 114.6 seconds. The operator chose Quit before Start and the app exited normally after 147.8 seconds. | H12 consumed its single launch. No advanced samples were acquired. Normal Stop on the SMC1500I and longer monitoring remain open. |
| E74 base app and E80 local package | The E74 base archive contains 83 members, nine backend modules, 25 runtime notice files and eight native notice files. E80 replaced only `RuntimeNotices/README.md` and `RuntimeNotices/manifest.json` from the final E79 delivery project archive; the other 23 runtime notice payloads were byte-identical and all eight native notices matched the E79 checksum inventory. The resulting E80 archive is `UPS-Monitor-0.1.0-preview.1-macOS-local.tar.gz` (SHA-256 `fa52c17c719127acb2d85aed6f3cc08f162094b8429e4332c827a32ba46a5eb6`). | The E80 archive was restored with `/usr/bin/tar -xzpf`; all 83 members retained byte, mode and link parity, and four signatures (outer app, widget, helper and producer) verified after extraction. This remains a local development package based on the E74 app, not a rebuild with the E79 native reader. GUI, app/UPS runtime, USB, downloaded installation and Gatekeeper assessment remain unqualified or NOT_RUN. See the [build inputs](OFFLINE_DEVELOPER_KIT.md) and [release gates](RELEASE_CHECKLIST.md). |
| E79 rebuilt native reader candidate | The E79 native recipe records an ARM64 product, minimum macOS 27.0, 403,760 bytes, mode `0600`, and a passing supervised static audit. | Static candidate only: not launched, signed, installed or tested with USB/UPS. The E80 package reuses the E74 app and its E73 native reader; it does not contain this E79 reader candidate. |
| E65 local SMC1500I package | Source-built arm64 producer, frozen helper, signed app and widget, nine backend modules and eight native notice files verified locally. | Apple Silicon, managed runtime minimum macOS 27.0. E65 has static package evidence. Device Stop, widget refresh during reading, downloaded installation and sustained operation remain open. See [local validation](LOCAL_VALIDATION_2026-11-04.md). |
| Build toolchain and offline checks | E54 recorded Xcode 27.1 (27A9275), Swift 6.4, Python 3.15.2 and macOS SDK 27.0; the full local check passed on its frozen copy. E55 later passed 36 targeted tests and verified a file-only copy of the synthetic runtime. | Historical toolchain snapshots, not a current toolchain matrix or a clean-room rebuild. E55 did not repeat E54's full check. |
| Swift/UI deployment declaration | The Swift package and app UI target declare macOS 14+. | This declaration is distinct from the E79 native reader candidate minimum of macOS 27.0; neither setting alone proves runtime compatibility on the declared minimum. |
| Intel Mac | No local runtime evidence recorded | Not qualified. |
| Native Apple power-source path | Historical observations include a native service read and a production-mode app session on 2026-10-11. The service enumerated one UPS and the internal Mac battery; the app selected the UPS and showed online status, reported battery voltage and a derived charge ratio. AC voltage, active/apparent power, current, temperature and runtime were unavailable in that observation. | Point-in-time capability observations only. No accuracy, LCD-agreement, multi-device or long-duration qualification. See [native baseline](NATIVE_BASELINE.md). |
| Experimental `apcmicrolink` hardware path | H09 (2026-10-28) historically recorded reported battery charge, estimated runtime, load, voltage, current, frequency and temperature fields. Active watts and apparent volt-amperes were derived from load percentages and nominal ratings; no Wh/kWh counter was present. The session ended `failed/guard_error`, so clean Stop was not established. H10 did not start the app or access USB because signature verification stopped its preflight. | Hardware use occurred historically, but the path is not qualified for daily use. H10 added no hardware observation. No accuracy, sustained-operation or clean-Stop claim. No individual sample values are reproduced here. |
| Synthetic E51 app and managed session | E57 (2026-11-04) observed one synthetic GUI session: Start, two fixture samples (charge 90→91%; estimated runtime 3,000→2,995 s), Stop and Quit. The managed receipt records two samples, cancellation with return code 0, quiesced consumer/publisher, resolved ownership and a stopped shared-store snapshot. | Synthetic control and data-path observation only; all values are fabricated. It does not qualify hardware behavior or daily use. |
| NUT model/data path | Synthetic decoder and client fixtures; patched `upsc` interop fixture uses a temporary loopback server | Synthetic only; no live NUT server or UPS compatibility demonstrated by these fixtures. |
| Experimental `apcmicrolink` source and package | The offline build compiled the pinned NUT/HIDAPI reader. The local managed app package includes it. | Ordinary app startup selects Apple power sources. Advanced acquisition requires an explicit managed session. |
| NUT stable 2.8.5 | Dependency baseline records that this version does not contain `apcmicrolink` | Does not imply compatibility for other NUT devices or drivers. |
| Widget extension | E58 observed an earlier stopped fixture. On 2026-11-06 the system-hosted E70 medium widget was identified on the desktop. It displayed the ordinary fixture at 74%, estimated runtime 35 min, derived 180 W and 215 VA. Following normal Quit it displayed **Stopped · stale · On line** and retained the readings. | E70 first showed **Shared data unavailable**. The live widget still displayed an older capture immediately after an app refresh. The separately supervised E70 app timed out before managed acquisition started. The visible transition covers the ordinary synthetic fixture. Freshness during managed collection, its Stop button, and real-device widget behavior remain open. See [visual evidence](SCREENSHOTS.md). |
| Offscreen visual probe | Eight synthetic widget/menu/energy component canvases rendered locally with ImageRenderer | Partial raster review only. Progress controls are placeholders; the ordinary/accessibility-requested pair was pixel-identical. No installed-widget, enlarged-text or VoiceOver qualification. |
| Earlier production UI and history | On 2026-10-11, a production-mode app session showed fresh native UPS data; manual refresh, history controls, short exports and normal quit/reopen were observed. | These historical checks do not establish current compatibility, driver behavior, full UI coverage, VoiceOver support or daily-use qualification. |
| Energy estimates | Synthetic active-watt integration and host tests passed. A synthetic app window showed Wh, coverage and gaps. H09 provided data for deriving UPS watts. | Real-session Wh coverage and comparison with a reference energy meter remain unverified. |

H09/H10 and the later E57 synthetic observation are distinct evidence. A
successful synthetic session does not resolve H09's failed clean Stop, and the
H10 preflight block is not a new hardware failure. Historical evidence remains
scoped to its recorded session and build.

The qualitative native capability record is in [NATIVE_BASELINE.md](NATIVE_BASELINE.md); it is not a
device, USB or protocol compatibility test. NUT source/build and licensing
boundaries are in [NUT_FEASIBILITY.md](NUT_FEASIBILITY.md),
[NUT_GUARDS.md](NUT_GUARDS.md), [NUT_UPSTREAM_STATUS.md](NUT_UPSTREAM_STATUS.md),
and [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md).

No compatibility claim should be inferred from an SDK version, deployment
target, synthetic fixture, successful compile or source-level guard. Real driver
work has additional safety and consent gates; see
[RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md).
